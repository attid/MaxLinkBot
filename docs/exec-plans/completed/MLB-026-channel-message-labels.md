# MLB-026: Название канала в подписи входящих сообщений

## Контекст

MAX публикует сообщения канала с `sender=0`, потому что у публикации нет
отдельного пользователя-отправителя. Сейчас адаптер корректно сохраняет нулевой
sender, но Telegram получает подпись `[0 UnknownID ...]`, хотя reconcile уже
сохранил название канала и использовал его для topic.

Согласованный формат канальной публикации:
`[<название канала> <дата и время>]`. Выдуманный sender ID не показывается.

## Риски и открытые вопросы

- Канальный режим включается только для явного целочисленного `sender_id=0`;
  старые тестовые payload без `sender_id` сохраняют прежнее поведение.
- Если сохранённого названия нет, используется уже нормализованное
  `sender_name`, чтобы доставка сообщения не блокировалась.
- `local_max_test.py` не относится к задаче и не коммитится.
